中文 · 数据如何处理

本工具面向获授权的企业 Jazz/HEP 用户，用于工作项读取、排期、质量检查及本地任务。使用企业功能需要企业网络或 VPN、相应访问权限及现有 SSO 会话。本说明描述实际数据处理，不声称“零收集”。

1 · 发布者与联系标识

发布者与维护联系：HOLDONgoing（GitHub维护账号）。这是公开维护账号，不是法律姓名，也不表示企业数据控制者或企业背书。
支持：GitHub Issues。

公开 Issues 不是秘密通道。仅提交完全合成的复现信息；禁止发布密码、Cookie、Token、MFA、内网地址、企业/客户/项目/工作项信息、个人资料、原始诊断或附件。不提供已核实的私人收件渠道；不要把账号名当邮箱。

2 · 企业工作项与网络传输

扩展从其配置限定的企业 Jazz/HEP 服务读取工作项编号、标题、项目、状态、日期、工时/估算、排期及关系等信息，用于展示与分析。本公开说明不披露企业主机名。用户明确执行 HEP 同步时，所确认的业务变更会发送至该企业服务；不是所有数据都只留在本地。

企业 Jazz/HEP 及身份服务处理其服务端记录；服务器保留期、位置、法律依据、备份及跨境安排由相应组织负责解释。本说明不替企业作出保证，扩展维护者不能删除企业服务端数据。

3 · 浏览器与独立任务目录

  • 浏览器扩展本地存储包含偏好、语言、扫描/关闭项缓存、任务缓存及诊断。现有后台写队列对其管理的 storage.local 数据执行 50 MiB 上限；这不是所有磁盘数据的总上限。
  • 附件二进制和元数据可在扩展 IndexedDB 中缓存或暂存。My Work 请求捕获还可能在企业页面 sessionStorage / DOM 属性中暂存业务请求参数；它们不是公开上传。
  • 另行安装的 Windows Task Companion 通过本地 Native Messaging 在当前用户的独立本地任务目录保存任务、描述、提醒、附件及通知账本；父目录还保留初始化标记。任务目录独立于扩展安装。
  • Companion 为外部 Windows/.NET Framework 依赖，不在扩展 ZIP 内。它不负责下载代码、安装扩展或扩展自更新。不同获授权浏览器/profile 可共享任务目录，并非按 profile 隔离。

4 · SSO 与敏感权限

请求复用浏览器已有认证会话；需要交互时，用户在外部浏览器页面自行完成密码、MFA 等步骤。扩展不主动读取或保存密码/MFA，不调用 Cookie API 提取 Cookie 值作为凭据；manifest 没有 cookies 权限。浏览器仍会按其规则随请求发送会话凭据。

debugger 权限用于受控企业 My Work 采集页的网络捕获、响应读取及随包固定表达式执行，可接收浏览器网络事件元数据；不能据此承诺所有事件都绝不包含敏感字段。现有逻辑使用业务 URL、参数、响应等信息，不以读取登录凭据或监视任意浏览为用途。

tabs / activeTab / scripting 支持用户触发的页面采集与有界 SSO 恢复；storage / unlimitedStorage 支持本地业务缓存；nativeMessaging 支持任务文件；alarms / notifications 支持提醒；contextMenus 支持将工作项加入任务。站点访问仅限扩展配置限定的企业服务域。高敏权限及具体商店披露仍须审核。

English · How data is handled

This tool supports authorized corporate Jazz/HEP users with work-item reading, planning, quality checks and local tasks. Corporate features require network/VPN access, appropriate authorization and an existing SSO session. This notice describes data processing; it is not a “zero collection” claim.

1 · Publisher and contact identifier

Publisher and maintenance contact: HOLDONgoing (GitHub maintenance account), not a legal name or assertion of corporate controllership or endorsement.
Support: GitHub Issues.

Public Issues are not confidential. Use entirely synthetic reproductions. Do not post passwords, cookies, tokens, MFA, internal URLs, corporate/customer/project/work-item information, personal data, raw diagnostics or attachments. No verified private intake channel is offered; the account name is not an email address.

2 · Corporate work items and network transfers

The extension reads identifiers, titles, projects, states, dates, effort/estimates, scheduling and relationships from the corporate Jazz/HEP service restricted by its configuration for display and analysis. This public notice does not disclose corporate hostnames. Explicit user-initiated HEP synchronization sends confirmed business changes to that corporate service; not all data stays local.

Corporate Jazz/HEP and identity services handle their server-side records. Their organizations explain retention, server locations, legal basis, backups and cross-border arrangements. This notice gives no guarantees on their behalf; the extension maintainer cannot delete enterprise server data.

3 · Browser storage and independent task files

  • Extension-local storage holds preferences, language, scan/closed-item caches, task caches and diagnostics. The existing background write queue enforces 50 MiB for the storage.local data it manages; this is not a cap on all disk data.
  • Attachment binary data and metadata may be cached or staged in extension IndexedDB. My Work request capture may also temporarily place business request parameters in corporate-page sessionStorage / DOM attributes; this is not public uploading.
  • A separately installed Windows Task Companion uses local Native Messaging to save tasks, descriptions, reminders, attachments and notification records in the current user's independent local task directory. Its parent directory also retains an initialization marker. This storage is independent of the extension installation.
  • The companion is an external Windows/.NET Framework dependency, excluded from the extension ZIP. It does not download code, install extensions or self-update the extension. Authorized browsers/profiles may share the task directory; it is not profile-isolated.

4 · SSO and sensitive permissions

Requests use the browser's existing authenticated session. If interaction is needed, the user completes password/MFA steps in an external browser page. The extension does not actively read or store passwords/MFA, or call a Cookie API to extract Cookie values as credentials; the manifest has no cookies permission. The browser still sends session credentials under its own rules.

The debugger permission supports network capture, response reading and bundled fixed expressions in controlled corporate My Work collection pages. It can receive browser network-event metadata; this is not a guarantee that every event is free of sensitive fields. Existing logic uses business URLs, parameters and responses, not login-credential extraction or arbitrary browsing surveillance.

tabs / activeTab / scripting support user-triggered collection and bounded SSO recovery; storage / unlimitedStorage support local business caches; nativeMessaging supports task files; alarms / notifications support reminders; contextMenus supports adding work items to tasks. Host access is restricted to the corporate service domain defined in the extension configuration. Sensitive permissions and store disclosures still require review.

5 · Diagnostics, exports and recipients

Diagnostics, issue snapshots and user-initiated JSON/Excel/attachment exports may contain business identifiers, titles, projects, user-supplied content, environment versions and sanitized errors. Sanitization is bounded, not an anonymity guarantee. Review files and recipient authorization before sharing. There is no automatic support upload, advertising or analytics telemetry; user-shared files are handled by the chosen recipients.

Microsoft/Google handle store information and uploaded materials under their own policies. The extension does not download remote executable JavaScript, poll repository releases or self-update; browser/store mechanisms handle extension updates.

GitHub Pages hosts this privacy site and GitHub Issues provides support. GitHub Pages logs visitor IP addresses for security purposes. GitHub may process IP addresses, browser requests, account information, posts and attachments when you visit or post, under the official GitHub Privacy Statement. This static page adds no scripts, forms or analytics; that does not mean the hosting provider processes no access data.

6 · Retention, deletion and backups

  • Preferences and browser caches have no uniform age-based expiry; they remain until replaced, cleared by the user or removed on uninstall, subject to browser behavior. A new extension ID cannot automatically access the old ID's data.
  • The persistent diagnostic log holds at most 200 entries, not a time-based retention period. Notification reconciliation removes records older than 90 days and applies a 10,000-record safety limit. Recent records are protected for deduplication and excess can block new entries; this is not a scheduled erasure guarantee. Consumed/cancelled snoozes are generally retained for about one day during reconciliation; unconsumed entries follow separate handling.
  • No uniform automatic expiry is promised for local tasks/attachments. Extension or companion uninstall does not delete the independent task directory or initialization marker. Back up first, then use an approved process to remove tasks, attachments, caches, markers and backups; deleting one directory is not complete erasure.
  • Exported files, downloaded attachments, OS/corporate backups and Jazz server records are not automatically deleted by extension uninstall. Arrange deletion at the corresponding locations with the responsible parties.

7 · Data requests and user choices

Contact your organization and enterprise service administrators for enterprise-data access, correction, deletion, jurisdiction or legal-basis questions. The extension maintainer cannot respond on their behalf or delete enterprise server data. Use GitHub's official procedures for GitHub account/post requests. Contact the maintenance account via Issues for local extension behavior only without sensitive details; no jurisdiction, legal response deadline or legal guarantee is invented.

You may stop using, disable or uninstall the extension, restrict permissions and clear relevant local data after backing up. Revoking permissions does not undo HEP changes or remove exports. Do not post identity or enterprise-data evidence in public Issues; ask your organization for its approved secure channel.
