中文 · 隐私说明草稿

本工具面向获授权的企业 Jazz 服务用户，支持工作项读取、排期、质量检查及本地任务。企业功能需要相应网络访问、权限和认证会话。本草稿描述数据处理，不声称零收集，也不代表企业背书。

1 · 维护者与联系

公开 GitHub 维护者账号：HOLDONgoing。此账号不等于已核验的法定控制者身份。一般支持可使用本独立仓库的公开 Issues：https://github.com/HOLDONgoing/jazz-sprint-monitor-privacy/issues。

Issues 完全公开。请勿发布个人信息、企业敏感信息、业务数据、附件、诊断原件或密码、会话 Cookie、令牌等安全凭据。私密请求渠道及正式隐私权申请流程尚待确定，请勿在公开 Issues 提交私密材料。

2 · 企业数据与用户发起的传输

扩展从获授权的企业 Jazz 服务读取工作项编号、标题、项目、状态、日期、工时、排期及关系等，用于展示与分析。用户明确发起并确认业务更新时，相关变更会发送至企业服务；并非所有数据都只留在本地。

企业 Jazz 与身份服务处理其服务端记录。其访问权限、服务器位置、保留期、法律依据及跨境安排须由负责方确认，本草稿不替这些服务作出保证。

3 · 本地缓存、任务、附件与提醒

  • 浏览器本地存储包含偏好、语言、工作项/关闭项缓存、任务缓存及诊断。当前后台写队列对其管理的扩展本地存储执行 50 MiB 上限，并非所有磁盘数据的总上限。
  • 附件二进制和元数据可能在扩展 IndexedDB 缓存或暂存。受控企业采集页的业务请求参数也可能暂存在该页面的 sessionStorage 或 DOM 属性中。
  • 另行安装的本地任务 companion 通过 Native Messaging 保存任务、描述、提醒、附件、通知记录及初始化标记。任务文件独立于扩展安装；获授权的浏览器配置可能共享该目录。
  • 浏览器提醒和通知用于任务提示；可受浏览器、操作系统及通知权限影响。本静态隐私网页不请求通知权限。

4 · 认证与敏感权限

SSO 由企业服务和身份服务负责。需要交互时，用户在外部浏览器自行完成密码及 MFA；扩展不以主动读取或保存密码/MFA 为功能，也不调用 Cookie API 提取 Cookie 值作为凭据。浏览器仍会按其规则随请求发送会话凭据。

受控采集使用页面访问、脚本及 debugger 等敏感能力，可暂存业务请求对象并接收网络事件元数据。因此不能绝对保证扩展处理的所有对象均不含 Cookie 或其他敏感字段；这不等于以提取登录凭据或监视任意浏览为用途。

5 · 诊断、导出与遥测边界

用户主动导出的诊断、快照、JSON/Excel 或附件可能含业务编号、标题、项目、填写内容、环境版本及脱敏错误。脱敏不保证匿名；分享前须检查内容与接收方授权。没有自动支持上传、广告或分析遥测；本公开页面及本次隐私仓库不新增遥测。

本页仅含静态 HTML 与内嵌 CSS，无脚本、远程字体、图片、追踪器、表单或外部可执行资源；离线亦可阅读。链接仅在主动打开时访问 GitHub 服务或官方文档。本页托管并不发布插件代码，也不向此仓库自动发送企业业务数据。

6 · 保留、删除与备份

  • 偏好与浏览器缓存没有统一按天到期规则；可被替换或由用户清除相关扩展数据，卸载效果取决于浏览器。新扩展身份不能自动读取旧身份的数据。
  • 当前持久诊断日志最多 200 条，并非按天删除。通知协调会清理超过 90 天的记录，另有 10,000 条安全限制；近期去重保护及超限拒绝可能适用，这不是定时擦除保证。
  • 本地任务和附件没有统一自动到期承诺。扩展或 companion 卸载不会自动删除独立任务文件、附件及初始化标记；请先备份，再分别清理缓存、本地任务与附件、标记及备份。
  • 导出文件、下载附件、操作系统或企业备份，以及企业服务端记录，不会因卸载扩展而自动删除；须在对应位置与负责方安排处理。

7 · GitHub 托管与未决事项

访问 GitHub Pages 时，GitHub 会为安全目的记录访问者 IP 地址，并可能按其政策处理其他技术数据；这独立于本页没有自建追踪器的事实。参见 GitHub Pages 数据收集说明及 GitHub 隐私声明。公开 Issues 的内容也由 GitHub 托管且可被他人查看。

正式发布前仍须确认法定控制者、有效私密联系渠道、适用法域与隐私权程序、法律依据、正式保留政策、托管访问与跨境安排。不虚构法律保证或固定期限。可停用/卸载、限制权限并备份后清理本地数据；这不会撤回已发送的业务变更。

本公开草稿不是已批准的最终政策，不能用于正式商店提交。

English · Draft privacy notice

This tool supports authorized corporate Jazz users with work-item reading, planning, quality checks and local tasks. Corporate features require appropriate network access, permissions and an authenticated session. This draft describes processing; it is not a zero-collection claim or corporate endorsement.

1 · Maintainer and contact

Public GitHub maintainer account: HOLDONgoing. This account is not a verified legal controller identity. General support is available through this independent repository's public Issues: https://github.com/HOLDONgoing/jazz-sprint-monitor-privacy/issues.

Issues are public. Do not post personal information, confidential corporate information, business records, attachments, raw diagnostics or security credentials such as passwords, session cookies or tokens. A private request channel and formal privacy-rights procedure are still to be determined. Do not submit private material in public Issues.

2 · Corporate data and user-initiated transfers

The extension reads identifiers, titles, projects, states, dates, effort, scheduling and relationships from authorized corporate Jazz services for display and analysis. Explicitly initiated and confirmed business updates send the relevant changes to the corporate service; not all data stays local.

Corporate Jazz and identity services process their own server-side records. Access controls, server locations, retention, legal basis and cross-border arrangements require confirmation by the responsible parties. This draft makes no guarantees on their behalf.

3 · Local caches, tasks, attachments and reminders

  • Browser-local storage holds preferences, language, work-item/closed-item caches, task caches and diagnostics. The current background queue caps the extension-local storage it manages at 50 MiB; this is not a cap on all disk data.
  • Attachment binary data and metadata may be cached or staged in extension IndexedDB. Business request parameters may also be temporarily placed in sessionStorage or DOM attributes on controlled corporate collection pages.
  • A separately installed local task companion uses Native Messaging to save tasks, descriptions, reminders, attachments, notification records and an initialization marker. These files are independent of the extension installation; authorized browser profiles may share the directory.
  • Browser reminders and notifications provide task alerts, subject to browser, operating-system and permission behavior. This static privacy webpage does not request notification permission.

4 · Authentication and sensitive permissions

Corporate and identity services provide SSO. Users complete password and MFA interaction in an external browser. The extension is not designed to actively read or store passwords/MFA, and does not call a Cookie API to extract cookie values as credentials. The browser still sends session credentials under its own rules.

Controlled collection uses sensitive capabilities including page access, scripting and debugger access. It may temporarily retain business request objects and receive network-event metadata. It is therefore not an absolute guarantee that every processed object is free of cookies or other sensitive fields; credential extraction and arbitrary browsing surveillance are not its purpose.

5 · Diagnostics, exports and telemetry boundaries

User-initiated diagnostic, snapshot, JSON/Excel and attachment exports may contain business identifiers, titles, projects, entered content, environment versions and sanitized errors. Sanitization does not guarantee anonymity. Review content and recipient authorization before sharing. There is no automatic support upload, advertising or analytics telemetry; this public page and privacy repository add no telemetry.

This page contains only static HTML and inline CSS: no scripts, remote fonts, images, trackers, forms or external executable resources. It is readable offline. Links access GitHub services or official documentation only when opened. Hosting this page does not publish extension code or automatically send corporate business data to this repository.

6 · Retention, deletion and backups

  • Preferences and browser caches have no uniform age-based expiry. They may be replaced or cleared by the user; uninstall behavior depends on the browser. A new extension identity cannot automatically access the old identity's data.
  • The current persistent diagnostic log holds at most 200 entries, not a time-based retention period. Notification reconciliation removes records older than 90 days and applies a 10,000-record safety limit; recent deduplication protection and refusal of new entries may apply. This is not scheduled erasure.
  • No uniform automatic expiry is promised for local tasks or attachments. Uninstalling the extension or companion does not automatically delete independent task files, attachments or initialization markers. Back up first, then separately clear browser caches, local tasks and attachments, markers and backups.
  • Exports, downloaded attachments, operating-system/corporate backups and corporate server records are not automatically deleted by extension uninstall. Arrange handling at the relevant locations with the responsible parties.

7 · GitHub hosting and unresolved decisions

When GitHub Pages is visited, GitHub logs visitor IP addresses for security and may process other technical data under its policies. This is separate from the absence of page-owned trackers. See GitHub Pages data collection and the GitHub Privacy Statement. Public Issues are also hosted by GitHub and visible to others.

Before a final release, confirm the legal controller, effective private contact channel, applicable jurisdiction and privacy-rights process, legal basis, formal retention policy, hosting access and cross-border arrangements. No legal guarantee or fixed period is invented. You may disable/uninstall, restrict permissions and clear local data after backing up; this does not undo submitted business changes.

This public draft is not an approved final policy and must not be used for a formal store submission.
